These powers remain under the current code.

The recorded release retains an upgrade key.

At the recorded release, one upgrade key could replace the program code, with no enforced timelock. It was not immutable. The live code check reports whether that key is still retained, changed or absent.

Inspect the recorded upgrade authority

Token-holder allocations trust a publisher.

The program checks funds, Merkle proofs and repeat claims. It does not verify historical token ownership or the fairness of the publisher’s allocations. A malicious publisher could allocate unreserved holder funds to itself. The game creator can replace this publisher.

Inspect published reward epochs

Game outcomes follow transaction order.

Under the current code, anyone can settle an expired round. The last eligible buyer wins the jackpot; there is no enabled random lottery. Bots, transaction ordering and network congestion can affect who gets the final buy.

Existing claims have defined protections.

Under the current code, published holder epochs cannot be rewritten and reserved claims are wallet-bound. The treasury can withdraw its accrued community allocation. These limits do not stop an upgrade authority replacing the code.

Read it. Check it yourself.

PIGGY’s program, interface and operator code are public. The recorded Rust source digest matches the inputs used for this release. A clean independent source-to-binary build has not been verified.

  1. Check the live release.

    Use “Check live program” on the first tab. No wallet is needed. It reads finalized mainnet accounts and compares the executable SHA-256.

  2. Use your own RPC.

    Clone the public repo and run its read-only checker. It checks the cluster, loader, ProgramData, complete executable and upgrade authority.

    git clone https://github.com/piggycasa/piggy.git
cd piggy
node tools/verify-release.mjs --rpc YOUR_MAINNET_RPC_URL
  3. Rebuild the source.

    The pinned source, Cargo.lock and recorded toolchain are published. Build with cargo build-sbf --manifest-path program/Cargo.toml --sbf-out-dir target/deploy --no-default-features -- --locked, then compare hashes. A mismatch is a failed reproduction; don’t treat the source as independently verified.

Recorded toolchain: cargo-build-sbf 4.0.0, platform-tools 1.53, rustc 1.89.0. Source commit: f7ba440e8667dd920d89bf6a8fba0158c3887e68.
